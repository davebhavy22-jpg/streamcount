Overview

Count unique visitors.

StreamCount demonstrates HyperLogLog, a probabilistic algorithm that estimates the number of unique visitors using a compact set of registers instead of storing every visitor ID.

Concept

How it works — three steps

Every visitor event goes through the same three steps. No visitor ID is ever stored.

1

Hash

Each visitor ID is transformed into a binary hash.

visitor-0042 → 64-bit hash
A good hash spreads IDs uniformly at random over all bit patterns.
2

Register

The hash is used to select a register and determine the relevant pattern.

top 10 bits → register index (0–1023)
next bits → count leading zeros (ρ)
The register keeps the maximum ρ seen so far.
3

Estimate

The information stored in registers is combined to estimate the total number of unique visitors.

Ê = αm · m² / Σ 2−M[j]
Registers with larger values contribute less — they signal a larger cardinality.

Hash → Register → Estimate  ·  repeated for every event in the stream

The mathematics

Probability & Statistics connection

HyperLogLog works because of a simple probabilistic fact about random bit patterns.

Why registers can estimate cardinality

  • Longer zero-runs are rarer. For a uniformly random hash, the probability that the first k bits are all zero is (1/2)k. A run of 5 zeros is about 32× less likely than a run of 0 zeros.
  • Registers capture the longest runs. Each register stores the maximum ρ (leading-zero count) seen for its share of hashes. The distribution of these maxima across 1,024 registers encodes how many distinct hashes were seen.
  • More distinct visitors → larger register values. With few visitors, most registers stay at 0. As more unique visitors arrive, registers fill in and their values grow — and the estimator inverts this relationship to recover the count.
  • Error shrinks with more registers. Averaging over m registers reduces variance, which is why the standard error falls as 1/√m.
Relative standard error
σ ≈ 1.04√m

Under the standard assumptions of HyperLogLog, the relative standard error is approximately 1.04 divided by the square root of the number of registers.

For m = 1,024:   σ ≈ 1.04 / √1024 ≈ 3.25%

This is a standard error — a typical size of deviation — not an absolute guarantee or a strict maximum error. Individual runs can be somewhat better or worse.

What StreamCount cannot do

  • It provides an estimate, not an exact count.
  • It cannot identify individual visitors.
  • Accuracy depends on the algorithm's assumptions and configuration.
  • It is not suitable where an exact count is required.
